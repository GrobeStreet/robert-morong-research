# PAVE — PE Target + Approach System

## Objective

Land the first real PAVE pilot by approaching PE firms that already have hands-on portfolio operations, software-heavy portfolios, and active AI/value-creation programs.

The first ask is not “buy PAVE” and not “hire us for AI transformation.” It is:

> Give us one portfolio company and one operating workflow. We will establish the human baseline, run a controlled shadow test, measure risk/quality/time/economics, and return a deploy / repair / kill recommendation before anything is scaled.

---

## 1. Who we target first

### Tier 1 profile

Prioritize firms that have all of the following:

- meaningful B2B / vertical SaaS exposure;
- an internal Growth, Portfolio Operations, Value Creation, Product/Tech, or AI team;
- a history of hands-on work inside portfolio companies;
- current interest in AI-enabled operating workflows;
- enough portfolio scale that a successful Pattern Card could be reused across multiple companies.

Do **not** start with mega-funds where procurement, security and internal AI programs create a long sales cycle unless there is a warm route in. Do **not** start with firms that are mostly passive financial sponsors.

The sweet spot is software-focused lower-middle-market / growth PE with 20–75 active platforms and an established operating team.

## 5. What we send

Do not send a long deck initially.

### First-touch package

1. **Short personalized note** — 100–160 words.
2. **PAVE PE one-pager** — the existing `pave/pe-facing-one-pager.md`, rendered cleanly when needed.
3. **Optional link to Pattern Card #001** only if they want the methodology or technical detail.

Never lead with the GitHub repository, benchmark hashes, code, or a technical architecture dump. Those are diligence assets after interest exists.

### What the one-pager must communicate in under two minutes

- problem: AI pilots generate claims, not always verified value;
- method: baseline → shadow intervention → deterministic controls → measured outcome;
- proof point: Renewal Operations Pattern Card #001 passed the synthetic hybrid benchmark;
- limitation: not yet production-proven and no claimed EBITDA;
- ask: one company + one workflow for a bounded pilot;
- output: deploy / repair / kill plus reusable Pattern Card.

## 6. First outreach note — structure

Do not use “AI agent,” “revolutionary,” “platform,” or “transform your portfolio.”

Use this structure:

**Line 1 — why them specifically**  
Reference their operating model, not a generic compliment.

**Line 2 — the problem**  
PE firms can launch many AI experiments; the hard part is proving which ones generate operating value after controls, review cost and implementation burden.

**Line 3 — what PAVE does**  
One workflow, frozen baseline, shadow run, deterministic controls around consequential actions, measured result.

**Line 4 — proof**  
We have completed the first renewal-operations Pattern Card in a synthetic controlled environment and deliberately separated AI interpretation from commercial arithmetic and permissions.

**Line 5 — ask**  
Would it be useful to compare the framework against one workflow in one portfolio company?

No pricing in the first note.

## 7. What the first conversation should sound like

The objective of call one is **not to sell a contract**. It is to identify one testable workflow and determine whether the firm has the data and operating sponsor to run a clean pilot.

### Opening — 60 seconds

> PAVE came from a simple problem: AI demos are easy; proving operating value is harder. We built a process that starts with the existing human workflow, freezes the baseline, lets AI handle the parts it is good at, puts deterministic controls around money, permissions and irreversible actions, and then measures the result. If the economics or reliability are not there, we kill it rather than force deployment.

### Then show the lesson from Case 001

> Our first test was renewal operations. The first version actually failed on pricing because the model used the wrong commercial source. Instead of prompting around it, we changed the architecture: deterministic code owns pricing and hard commercial rules; AI owns messy evidence interpretation and routing. The harder second benchmark passed. That failure-to-repair sequence is really the product — the measurement system tells us what should and should not be delegated to AI.

### Then turn the conversation toward them

Ask:

1. Where across your portfolio are teams already experimenting with AI but struggling to quantify whether the workflow is actually better?
2. Which recurring operating workflows consume meaningful human time and have enough historical cases to establish a baseline?
3. Which company has a strong functional owner who would tolerate a shadow-mode experiment?
4. What would you need to see before allowing an AI-assisted workflow to move from shadow mode to production?

### Close

> If we can find one workflow where the data exists and the outcome is measurable, the next step is small: historical sample, current policy, human baseline and a defined safety envelope. We run it in shadow mode and come back with deploy, repair or kill. No production access is required for the first test.

## 8. What makes a good first pilot

Choose a portfolio company where:

- the workflow happens frequently enough to generate a meaningful sample;
- there is a clear current human process;
- input data can be exported without a long integration project;
- the outcome can be scored objectively;
- mistakes can be contained in shadow mode;
- the functional leader already feels the pain;
- the workflow exists in other portfolio companies if it succeeds.

Best initial workflow categories:

1. renewal/customer-success preparation;
2. quote/pricing exception routing;
3. accounts-receivable / collections prioritization;
4. customer onboarding / implementation preparation;
5. service or support escalation triage.

Do not begin with autonomous legal decisions, firing/hiring, capital allocation, contract modification or anything where the first experiment requires irreversible live actions.

## 9. Commercial sequence

### Stage 0 — relevance check
15–25 minute conversation. No fee discussion unless they ask.

### Stage 1 — workflow qualification
Identify company, process owner, data, baseline metric and safety envelope.

### Stage 2 — fixed-scope paid pilot
Price only after scope. Early target range can be approximately **$15k–$30k** for a tightly bounded workflow study, but the scope and access burden should determine the quote rather than an arbitrary standard price.

### Stage 3 — implementation / second Pattern Card
If the controlled pilot passes, either help deploy that workflow or test the next reusable portfolio workflow.

### Stage 4 — portfolio program
Only after multiple real-company wins: cross-portfolio workflow library, benchmark corpus, Pattern Cards, implementation templates and recurring value measurement.
